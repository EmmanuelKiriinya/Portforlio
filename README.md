# Emmanuel Kiriinya — portfolio

A data science portfolio with a full content management system. Nothing on the
public site is hardcoded: every section is edited through `/admin`.

- **Frontend** — Next.js 15 (App Router) + TypeScript + Tailwind v4 → **Vercel**
- **Backend** — FastAPI + SQLAlchemy 2 + Alembic → **Render**
- **Database** — **Neon** Postgres
- **Media** — **Cloudflare R2** (S3-compatible, swappable)
- **Icons** — Icons8, with a lettered fallback when an icon is missing

Design rationale — palette, type, the pattern budget — is in [DESIGN.md](./DESIGN.md).

```
├── backend/     FastAPI service, migrations, seed data
├── frontend/    Next.js site and admin panel
└── DESIGN.md    the design plan and its review
```

## 1. Run it locally

Two terminals. The backend first, since the frontend reads from it at build time.

### Backend

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# For a first local run you can leave DATABASE_URL pointing at Postgres, or use
# SQLite with no setup at all:
#   DATABASE_URL=sqlite:///./local.db
#   STORAGE_BACKEND=local
#   COOKIE_SECURE=false
#   COOKIE_SAMESITE=lax

alembic upgrade head        # create the schema
python -m app.seed          # realistic starting content + your admin user

uvicorn app.main:app --reload --port 8000
```

API docs at http://localhost:8000/docs (disabled automatically in production).

### Frontend

```bash
cd frontend
npm install

cp .env.example .env.local   # defaults already point at localhost:8000
npm run dev
```

Site at http://localhost:3000, CMS at http://localhost:3000/admin.
Sign in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` from `backend/.env`, then
change the password under **Site settings → Change password**.

## 2. Deploy the backend to Render

### 2a. Create the Neon database

1. Create a project at [neon.tech](https://neon.tech).
2. Copy the **pooled** connection string (it contains `-pooler`).
3. Keep `?sslmode=require` on the end.

### 2b. Create the Render service

`render.yaml` is a blueprint — in the Render dashboard choose
**New → Blueprint** and point it at this repository. It sets `rootDir` to
`backend`, runs `alembic upgrade head` at boot, and health-checks `/health`.

Then set these in the Render dashboard (they are deliberately not in the file):

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Neon pooled string |
| `CORS_ORIGINS` | `https://your-site.vercel.app,https://yourdomain.com` |
| `ADMIN_EMAIL` | your sign-in address |
| `ADMIN_PASSWORD` | a long passphrase, used once by the seed |
| `ADMIN_NAME` | your name |
| `R2_ACCOUNT_ID` | Cloudflare account id |
| `R2_ACCESS_KEY_ID` | R2 API token id |
| `R2_SECRET_ACCESS_KEY` | R2 API token secret |
| `R2_BUCKET` | e.g. `portfolio-media` |
| `R2_PUBLIC_BASE_URL` | your R2 public domain, e.g. `https://media.yourdomain.com` |

`SECRET_KEY` is generated by Render. `ENVIRONMENT=production` makes the app
refuse to boot on a default secret and hides `/docs`.

`CORS_ORIGINS` accepts `a,b,c` or a JSON array. It must list **every** origin
the browser will use — including your Vercel preview domains if you want the
CMS to work from those.

### 2c. Seed production once

From the Render shell, after the first deploy:

```bash
python -m app.seed
```

Then sign in and change the password immediately.

## 3. Set up Cloudflare R2

1. Cloudflare dashboard → **R2** → create a bucket (e.g. `portfolio-media`).
2. **Settings → Public access** → connect a custom domain, e.g.
   `media.yourdomain.com`. That hostname is `R2_PUBLIC_BASE_URL`.
3. **Manage R2 API Tokens** → create a token with **Object Read & Write**
   scoped to that bucket. Copy the id and secret.

Free tier: 10 GB storage and **no egress charges**, which is what matters for
an image-heavy site.

Uploads are downscaled to 1920px and stored alongside a WebP derivative, which
the site prefers. Swapping to S3, Backblaze, or MinIO is a change to
`STORAGE_BACKEND` and the credentials — no code changes.

## 4. Deploy the frontend to Vercel

1. **New Project** → import the repo → set **Root Directory** to `frontend`.
2. Environment variables:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://your-api.onrender.com/api/v1` |
| `NEXT_PUBLIC_SITE_URL` | `https://yourdomain.com` |
| `NEXT_PUBLIC_MEDIA_HOST` | `media.yourdomain.com` (hostname only, no protocol) |

3. Deploy, then go back and add the Vercel domain to `CORS_ORIGINS` on Render.

Finally, in the CMS under **Site settings**, set **Site URL** to your real
domain — canonical links, Open Graph tags, and `sitemap.xml` are generated
from it.

### The Render free tier sleeps

A free Render service spins down after ~15 minutes idle, so the first request
after a quiet period takes 30–60 seconds. Public pages use ISR
(`revalidate = 300`), so visitors normally hit Vercel's cache rather than a
cold API — but the CMS will feel slow on first use. Upgrading to Render's
paid tier removes the sleep.

## 5. What the CMS covers

Everything the public site shows:

| Section | Where |
|---|---|
| Hero, bio, statistics, expertise | Profile & about |
| Roles and quantified achievements | Experience |
| Degrees | Education |
| Skills carousel (Icons8 URLs) | Skills |
| Project case studies | Projects |
| Articles with code, tables, images | Blog posts |
| Credentials and verification links | Certifications |
| Testimonials with LinkedIn links | Testimonials |
| Uploads, alt text, folders | Media library |
| Resume link, contact, SEO, theme | Site settings |
| Categories, tags, social links | Categories & tags |
| Contact form submissions | Messages |

Notes on behaviour worth knowing:

- **Resume** takes a Google Drive share link and converts it to a direct
  download automatically. A plain PDF URL works too.
- **Live demo** buttons render only when a URL exists — never as a dead button.
- **Blog deletes are soft.** Deleted posts go to **Trash** and can be restored.
- **Featured** content drives the homepage. If nothing is marked featured, the
  homepage falls back to the most recent work so it is never empty.
- **Project case-study sections** (Problem, Data, Methodology, Models, Results)
  are each optional and hidden when blank.

## 6. Adding skill icons

Paste any SVG or PNG URL into the icon field. Three sources cover nearly
everything, in order of preference:

| Source | Best for | URL shape |
|---|---|---|
| [Devicon](https://devicon.dev) | Languages and data tooling, full colour | `https://cdn.jsdelivr.net/gh/devicons/devicon@latest/icons/NAME/NAME-original.svg` |
| [Iconify](https://icon-sets.iconify.design/logos/) | Brand logos Devicon lacks, full colour | `https://api.iconify.design/logos:NAME.svg` |
| [Simple Icons](https://simpleicons.org) | Long tail; monochrome, you pick the colour | `https://cdn.simpleicons.org/NAME/f5b426` |

Icons8 URLs still work if you prefer them — the field accepts any URL.

A few tools (XGBoost, LightGBM) have no official mark anywhere. Leave the field
blank and the site renders a lettered tile in the brand colours. The same
happens if a URL 404s, so a wrong guess degrades quietly rather than showing a
broken image. Nothing ever falls back to an emoji.

These hosts are allow-listed in `frontend/next.config.ts`. Add any new one
there or `next/image` will refuse to load it.

## 8. Security

- Admin routes require a JWT delivered in an HTTP-only cookie; no token is ever
  readable from JavaScript.
- Passwords are bcrypt hashed. Login failures are deliberately indistinguishable
  so the form cannot be used to enumerate accounts.
- Rich text is sanitized server-side on write against an allowlist, so a
  compromised editor cannot inject script into visitors' pages.
- The contact form has a honeypot field and a duplicate guard.
- `/admin` is `noindex` and excluded in `robots.txt`.
- Secrets live only in environment variables. `.env` is git-ignored.
